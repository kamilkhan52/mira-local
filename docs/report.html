MIRA on the local workflow, with Jev

The memory weekly digest for 21–28 Sep 2026 (2,000 arXiv papers), run on 30 Sep by the original n8n workflow and by the new local workflow: once with Jev off (All LLM) and once at each of three Jev levels. Jev is a fast scoring model from TypeSafe. It decides which papers need the expensive per-paper LLM calls.

Summary

  1. The local workflow reproduces the n8n digest and runs unattended. A schedule or a single command runs everything, from arXiv to the delivered email. Replaying a real n8n daily run with identical inputs produced a byte-identical email.
  2. n8n could not produce this week's digest: every weekly attempt crashed after paper selection. After the fixes listed under Reliability, all four local runs completed and sent their digests.
  3. Jev cuts the weekly cost by 55–85% and the time by 27–65%. 16 of the 20 deep-dive papers were picked by every run, n8n included.
  4. Recommendation: the Jev gate level for weekly digests. It costs $11.84 instead of $35.68 and takes 15 minutes instead of 25. Its shortlist and picks are as close to an all-LLM run as two all-LLM runs are to each other.
  5. New: a live news agent. It checks the news sources every hour and alerts only on relevant articles. A run takes about a minute and costs a fraction of a cent when nothing is new.

What the Jev levels do

TypeSafe's Jev model returns a score in about 0.1 s per item and does not write text. The levels differ only in which papers get the two per-paper LLM calls, credibility and relevance. Selection, deep analysis, report and email are the same LLM steps at every level.

The live news agent

Per run: EE Times, SemiAnalysis and TrendForce crawled in parallel

For Jev to score each new article
< $0.001
A quiet run (nothing new)
≈ $0.007
Per article alerted, for its LLM-written summary

Every hour the agent crawls the news sources and skips anything already seen. Jev scores each new article against the profile's focus. Only the articles that pass get a two- to three-sentence LLM summary written for that profile, and those go out in a short email. Paper alerts are off by default: new papers appear once a day and are covered by the weekly digest.

Measurements and settings
  • The first run found 6 articles worth sending; the alert, including summaries, cost $0.04. Quiet runs cost about $0.0003 in Jev calls.
  • Runs took about 4.5 minutes until the crawlers were made to run in parallel and the Digitimes crawler was switched off. Digitimes times out after 180 s without returning anything.
  • Subscribers, sources, the item limit and paper alerts (include_papers) are set in configs/realtime.json. The hourly schedule is realtime-hourly in configs/schedules.json.

Background

The local workflow in brief
  • What it is: the n8n workflow rebuilt in Python on Prefect (Apache-2.0), running on one machine, with a local UI for run history, logs and manual runs. There is no n8n or Docker, and telemetry is off.
  • Parity: replaying a real n8n daily run gave every LLM step identical inputs and produced a byte-identical email.
  • Profiles unchanged: 6 profiles and 8 profile/mode combinations, each with its own prompts, thresholds, arXiv categories, email style, schedule and cache.
  • Data leaving the machine: calls to the LLM provider (configurable, e.g. a company gateway), to Jev, and to arXiv and the news sites.
Running it 
# one-off digest (the same code path the schedule uses)
.venv/bin/python run.py --profile memory-innovation --mode weekly --jev-level gate

# local scheduler and UI (http://127.0.0.1:4200)
make server   # terminal 1
make serve    # terminal 2 — schedules come from configs/schedules.json

# calibrate Jev for a profile from cached LLM judgments
.venv/bin/python scripts/bench_jev.py --per-profile 150

# reproduce this comparison
bin/mira-env python tools/experiment_weekly.py --current-date 2026-09-28
.venv/bin/python tools/experiment_analysis.py --current-date 2026-09-28

Each run writes a summary with time and cost per stage to data/runs/. This comparison's results are in docs/data/.

Method and caveats
  • Scope: one week and one profile (memory, weekly), 2,000 papers (the arXiv query cap). Jev's cutoffs for the other profiles come from about 600 past LLM judgments each.
  • Same inputs: all local runs read one saved arXiv response; n8n queried arXiv itself and got the same 2,000 papers.
  • PDFs: first pages were already cached for every run except the first local all-LLM run, which downloaded them in 3.5 minutes. Its time is shown without that download (25.2 minutes).
  • Cost: local costs are OpenRouter's reported cost per call, plus Jev at $0.042 per million input tokens. n8n's cost is its recorded token counts at OpenRouter's prices; that method matched the account balance within 5% on an earlier run. Balance changes couldn't be used on 30 Sep because the account auto-reloaded mid-run.
  • LLM caches: bypassed in every run, so each paid for all its LLM calls.
  • Lost calls: the local all-LLM run lost 10 of 4,021 LLM calls (before the retry fix). The n8n run shown (execution 2088) lost 98 relevance calls.
  • Test mode: all runs used it. Reports were stored as tests and emailed only to a test inbox, with the level tagged in the subject.
Data: docs/data/ in the mira-local repo. n8n executions 2087–2090 (four weekly attempts); the figures come from 2088.
