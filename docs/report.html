MIRA on the local workflow: Jev and in-house scoring

The memory weekly digest for 21–28 Sep 2026 (2,000 arXiv papers), run on 30 Sep by the original n8n workflow and by the new local workflow: once with Jev off (All LLM) and once at each of three Jev levels. Jev is a fast scoring model from TypeSafe. It decides which papers need the expensive per-paper LLM calls. On 1 Oct, two open models that can replace Jev in-house ran the same week at the gate level.

Summary

  1. The local workflow reproduces the n8n digest and runs unattended. A schedule or a single command runs everything, from arXiv to the delivered email. Replaying a real n8n daily run with identical inputs produced a byte-identical email.
  2. n8n could not produce this week's digest: every attempt at this week's digest crashed after paper selection. After the fixes listed under Reliability, all four local runs completed and sent their digests.
  3. Jev cuts the weekly cost by 37–85% and the time by 27–65%. 16 of the 20 deep-dive papers were picked by n8n and at every Jev level.
  4. Recommendation: the gate level now, and Kev-9B for the fully local deployment. With Jev, after a data-handling review of TypeSafe, a week costs $15.23 instead of $35.68 and takes 15 minutes instead of 25. Kev-9B is an open model that keeps scoring in-house, at $17.11 a week at today's LLM prices. It is to be piloted on a Micron GPU. See Keeping scoring in-house.
  5. New: a live news agent. It checks the news sources every hour and alerts only on relevant articles. A run takes about a minute and costs a fraction of a cent when nothing is new.

What the Jev levels do

TypeSafe's Jev model returns a score in about 0.1 s per item and does not write text. The levels differ only in which papers get the two per-paper LLM calls, credibility and relevance. Selection, deep analysis, report and email are the same LLM steps at every level.

Keeping scoring in-house

Jev is an outside service: each paper's title and abstract and each news article is sent to TypeSafe. The workflow is meant to run on Micron infrastructure, where that text should stay in-house and GPUs are available. A local model keeps it away from TypeSafe; the LLM calls still go to the configured LLM provider. Two open models (Apache-2.0) answer the same questions through the same interface: Kev-9B and Bespoke-Nimble-9B. Each got its own cutoffs from the same past LLM judgments as Jev, then ran the gate level on the same week. These tests ran on a Mac, so their speed is shown only as a reference.

Setup and next steps
  • Switching: the digest's jev_backend setting (typesafe, kev or nimble) picks the model; each has its own calibrated cutoffs. The code path is otherwise the same.
  • Kev-9B: uv run --extra serve python -m kev.serve --run jaredpalmer/kev-9b --port 8009 in a clone of jaredpalmer/kev. It downloads about 18 GB, needs about 17 GB of GPU memory, and uses CUDA on NVIDIA GPUs (MLX on a Mac).
  • Nimble-9B: needs Ollama 0.35 or later, served on its own port (11435 in this setup), so it can run beside another Ollama install. Ollama allows at most 26 options per question, so it skips the topic question; only relevance is used at the gate level.
  • First step: the cutoffs were calibrated on the earlier LLM's (Gemini 3.1 Pro's) judgments, so every profile needs one recalibration run on gpt-5.6-terra.
  • Not yet done: the live news agent still uses Jev; moving it to Kev needs Kev's news threshold calibrated (scripts/bench_jev_media.py). The prescreen and replace levels were not tested with local models.
  • Worth testing on a large GPU: Kev-27B (51 GB, needs an 80 GB GPU). Its authors report it within a point of Jev on sources Kev was not trained on (0.851 vs 0.857).

Every hour the agent crawls the news sources and skips anything already seen. Jev scores each new article against the profile's focus; until Kev's news threshold is calibrated, that means article text and the focus go to TypeSafe. Only the articles that pass get a two- to three-sentence LLM summary written for that profile, and those go out in a short email. Paper alerts are off by default: new papers appear once a day and are covered by the weekly digest.

Measurements and settings
  • The first run found 6 articles worth sending; the alert, including summaries, cost $0.04. Quiet runs cost about $0.0003 in Jev calls.
  • Runs took about 4.5 minutes until the crawlers were made to run in parallel and the Digitimes crawler was switched off. Digitimes times out after 180 s without returning anything.
  • Subscribers, sources, the item limit and paper alerts (include_papers) are set in configs/realtime.json. The hourly schedule is realtime-hourly in configs/schedules.json.

Background

The local workflow in brief
  • What it is: the n8n workflow rebuilt in Python on Prefect (Apache-2.0), running on one machine, with a local UI for run history, logs and manual runs. There is no n8n or Docker, and telemetry is off.
  • Parity: replaying a real n8n daily run gave every LLM step identical inputs and produced a byte-identical email.
  • Profiles unchanged: 6 profiles and 8 profile/mode combinations, each with its own prompts, thresholds, arXiv categories, email style, schedule and cache.
  • Data leaving the machine: calls to the LLM provider (configurable, e.g. a company gateway), to Jev unless a local scoring model is used, and to arXiv and the news sites.

Method and caveats
  • Scope: one week and one profile (memory, weekly), 2,000 papers (the arXiv query cap). Jev's cutoffs for the other profiles come from about 600 past LLM judgments each.
  • Same inputs: all local runs read one saved arXiv response; n8n queried arXiv itself and got the same 2,000 papers.
  • PDFs: first pages were already cached for every run except the first local all-LLM run, which downloaded them in 3.5 minutes. Its time is shown without that download (25.2 minutes).
  • Cost: local costs are OpenRouter's reported cost per call, plus Jev at $0.042 per million input tokens. The per-paper LLM calls are priced at the All LLM run's cost per call (for every Jev and local-model run): the prescreen and gate runs started within the hour after it, sent identical prompts, and were billed about 35% less through OpenRouter's prompt cache, a discount a normal weekly run doesn't get. Billed amounts are in docs/data/. n8n's cost is its recorded token counts at OpenRouter's prices; that method matched the account balance within 5% on an earlier run. Balance changes couldn't be used on 30 Sep because the account auto-reloaded mid-run.
  • MIRA's response cache: bypassed in every run, so every run made all of its LLM calls. OpenRouter's prompt-cache discount is a separate effect, covered under Cost.
  • Lost calls: the local all-LLM run lost 10 of 4,021 LLM calls (before the retry fix). The n8n run shown (execution 2088) lost 98 relevance calls.
  • Test mode: all runs used it. Reports were stored as tests and emailed only to a test inbox, with the level tagged in the subject.
Data: docs/data/ in the mira-local repo. n8n executions 2087–2090 (four weekly attempts); the figures come from 2088.
